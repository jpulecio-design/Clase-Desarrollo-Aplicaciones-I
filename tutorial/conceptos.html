Evolución Sistemas Computacionales

¿Qué es un Mainframe?

Un Mainframe es un computador de gran capacidad diseñado para procesar enormes cantidades de datos y ejecutar múltiples operaciones de manera simultánea, segura y confiable.

Los sistemas Mainframe son utilizados principalmente por bancos, entidades gubernamentales, compañías de seguros, aerolíneas y grandes organizaciones que requieren alta disponibilidad y procesamiento continuo de información.

Características principales

  • Alta capacidad de procesamiento.
  • Procesamiento de grandes volúmenes de datos.
  • Alta seguridad y confiabilidad.
  • Funcionamiento continuo las 24 horas.
  • Soporte para miles de usuarios y transacciones simultáneas.
Origen: Los sistemas Mainframe comenzaron a desarrollarse y popularizarse durante la década de 1960.

¿Qué es una Terminal Bruta?

Una Terminal Bruta (Dumb Terminal) es un dispositivo utilizado para interactuar con un computador central, que no posee capacidad significativa de procesamiento ni almacenamiento propio. Su función principal es permitir al usuario ingresar datos y visualizar la información que es procesada por el computador central.

La terminal bruta depende completamente del computador central o Mainframe para ejecutar programas, realizar cálculos y almacenar información. El terminal únicamente transmite las entradas del usuario y muestra los resultados recibidos.

Características principales

  • No realiza procesamiento complejo de manera independiente.
  • No requiere almacenamiento local significativo.
  • Depende de un computador central o servidor.
  • Permite ingresar comandos o datos.
  • Muestra los resultados enviados por el sistema central.
Año: Las terminales brutas se popularizaron durante las décadas de 1960 y 1970, especialmente con el uso de sistemas de tiempo compartido y computadores centrales.
Ejemplo: Una terminal conectada a un Mainframe que permite a los usuarios consultar información y ejecutar aplicaciones almacenadas y procesadas en el computador central.

¿Qué es el modelo Cliente-Servidor?

El modelo Cliente-Servidor es una arquitectura de software en la que las tareas se reparten entre dos roles bien diferenciados: los clientes, que solicitan recursos o servicios, y los servidores, que los proporcionan y procesan.

Es la base sobre la que funcionan la mayoría de aplicaciones actuales: navegadores web, correo electrónico, bases de datos, videojuegos en línea, banca electrónica, entre otros.

El modelo Petición - Respuesta

El corazón de esta arquitectura es el modelo petición-respuesta:

  1. El cliente envía una petición (request) al servidor a través de la red.
  2. El servidor recibe la petición, la procesa y consulta sus recursos.
  3. El servidor devuelve una respuesta (response) al cliente.
  4. El cliente recibe la respuesta y la presenta al usuario.

Roles principales

  • Cliente: inicia la comunicación, presenta la interfaz al usuario.
  • Servidor: escucha peticiones, procesa y responde; siempre está disponible.
  • Red: canal por el que viajan las peticiones y respuestas (HTTP, TCP/IP, etc.).

Ventajas

  • Centralización de datos y recursos.
  • Escalabilidad: se pueden añadir más clientes o más servidores.
  • Seguridad y control de accesos desde el servidor.
  • Mantenimiento más sencillo al estar la lógica en el servidor.
Año: El modelo Cliente-Servidor se consolidó en la década de 1980 con la expansión de las redes locales (LAN) y los sistemas distribuidos.
Ejemplo: Al abrir un navegador y visitar wikipedia.org, el navegador (cliente) envía una petición HTTP y el servidor de Wikipedia responde con el HTML de la página.

Arquitectura Cliente-Servidor de 2 Niveles

La arquitectura de dos niveles (two-tier) es la forma más básica del modelo Cliente-Servidor. En ella solo existen dos capas o niveles: el cliente y el servidor, que se comunican directamente a través de la red.

¿Cómo está compuesta?

  • Nivel 1 – Cliente (Presentación): contiene la interfaz de usuario, valida datos básicos y envía peticiones al servidor.
  • Nivel 2 – Servidor (Datos / Lógica): almacena la base de datos, ejecuta la lógica del negocio y responde al cliente.

Flujo petición-respuesta en 2 niveles

  1. El cliente envía una petición directamente al servidor.
  2. El servidor consulta su base de datos y procesa la lógica.
  3. El servidor devuelve los datos al cliente.
  4. El cliente muestra la información al usuario.

Características principales

  • Comunicación directa entre cliente y servidor.
  • Lógica de negocio y datos en el mismo servidor.
  • Fácil de implementar para sistemas pequeños.
  • Rendimiento rápido en redes locales pequeñas.
Año: Se popularizó en los años 80 y 90 con aplicaciones de escritorio que se conectaban directamente a bases de datos como Oracle, SQL Server o MySQL.
Ejemplo: Una aplicación de escritorio en Java o C# que se conecta directamente a una base de datos MySQL para consultar productos de un inventario.

Ventajas y desventajas

  • Sencilla y rápida de implementar.
  • Bajo costo inicial.
  • Poco escalable con muchos usuarios.
  • Difícil de mantener si la lógica crece.

Arquitectura Cliente-Servidor de 3 Niveles

La arquitectura de tres niveles (three-tier) separa la aplicación en tres capas independientes, cada una con una responsabilidad concreta. Esto permite mayor escalabilidad, seguridad y mantenimiento que el modelo de 2 niveles.

Las tres capas

  1. Capa de Presentación (Cliente): interfaz gráfica o web con la que interactúa el usuario. Solo se encarga de mostrar y capturar datos.
  2. Capa de Lógica de Negocio (Servidor de Aplicaciones): procesa las reglas del negocio, valida datos, hace cálculos y decide qué información pedir a la base de datos.
  3. Capa de Datos (Servidor de Base de Datos): almacena y gestiona la información; solo responde a la capa de lógica, nunca directamente al cliente.

Flujo petición-respuesta en 3 niveles

  1. El cliente envía una petición a la capa de lógica.
  2. La capa de lógica valida y consulta a la capa de datos.
  3. La capa de datos responde a la capa de lógica.
  4. La capa de lógica procesa y envía la respuesta al cliente.
  5. El cliente muestra el resultado al usuario.

Ventajas

  • Mayor escalabilidad y rendimiento.
  • Mejor seguridad (el cliente nunca toca la base de datos).
  • Mantenimiento independiente de cada capa.
  • Reutilización de la lógica de negocio para varios clientes (web, móvil, escritorio).
Año: Se popularizó a finales de los años 90 con el auge de las aplicaciones web y los servidores de aplicaciones (Java EE, .NET, PHP).
Ejemplo: Una tienda en línea: el navegador es la capa de presentación, el servidor con Node.js o Java es la capa de lógica, y MySQL o PostgreSQL es la capa de datos.
Arquitectura de 3 Niveles · 2026

Arquitectura Cliente-Servidor Multinivel (N-Niveles)

La arquitectura multinivel (o N-tier) es una evolución de la de 3 niveles en la que la aplicación se divide en múltiples capas independientes, cada una especializada en una función específica. Cada capa se comunica solo con las capas contiguas.

Capas típicas de un sistema multinivel

  • Presentación: interfaz de usuario (web, móvil, escritorio).
  • Servicios web / API: puerta de entrada al sistema (REST, GraphQL, SOAP).
  • Lógica de negocio: reglas y procesos del dominio.
  • Acceso a datos (DAO): capa que abstrae la base de datos.
  • Persistencia: base de datos, caché, almacenamiento en la nube.
  • Infraestructura: servidores, balanceadores, colas de mensajes.

Flujo petición-respuesta en multinivel

  1. El usuario interactúa con la capa de presentación.
  2. La petición pasa por la capa de servicios/API.
  3. Se ejecuta la lógica de negocio correspondiente.
  4. Se consulta la capa de acceso a datos.
  5. La base de datos responde con la información.
  6. La respuesta regresa por cada capa hasta llegar al usuario.

Ventajas

  • Máxima escalabilidad (cada capa puede escalar por separado).
  • Alta disponibilidad y tolerancia a fallos.
  • Seguridad reforzada por capas.
  • Ideal para microservicios y aplicaciones en la nube.
  • Mantenimiento y despliegue independiente por equipo.
Año: Su auge se da a partir de los años 2000 con el crecimiento de Internet, y se consolida del todo con la computación en la nube y los microservicios (2010 en adelante).
Ejemplo: Plataformas como Amazon, Netflix o Mercado Libre usan arquitecturas multinivel con decenas de microservicios, cada uno con su propia base de datos, comunicándose por APIs REST.
